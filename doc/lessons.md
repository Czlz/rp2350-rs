# 经验教训 / Lessons learned

本文件保留**仍然适用**的工程经验与踩坑记录，不再列举已解决的缺陷（那些已在 changelog 与
crate 文档中）。下一会话请先读本文件，再读 [`handoff.md`](handoff.md)。

## 1. 定位与语义

1. **不要用「这个固件用不到」裁剪语义**。`WFI`/`WFE`/`SEV`、阻塞 FIFO、总线 stall、
   外设复位值等都按数据手册/ARM ARM 实现；示例固件只决定**优先级**，不决定**是否需要**。
   （本会话曾把 WFI 划出性能路线，被用户纠正。）
2. **默认路径必须确定性**。任何「交互加速」（睡眠快进、双核线程）都要能关闭，关闭时逐字节
   等同旧路径；验收/回归一律用默认模式。
3. **子会话按规范纠正提示词是好事**。NMI 层级（`Reset > NMI > HardFault`）、PMP M 模式
   未锁定条目透明、`MMFAR/BFAR` 是读写地址字段、PIO 周期计时本来正确——都以 ARM ARM /
   特权规范 / 数据手册为准，不以提示词为准。

## 2. 测量与性能

4. **口径必须写清**：帧率、字速率、**i16 样本数**、**墙钟秒**与**客户机时间**混用会制造假象。
   - 「PIO 只有 2.7k 帧/秒」实际是把样本数除以墙钟秒；正确值是 **13 441.7 字/秒**。
   - 「play 12 fps」曾全部落在启动睡眠段；真实游戏段约 2 fps。
   - 性能数据必须按**工作负载窗口**报告（如 emerald 300–500 M），不得用启动/睡眠段代表整体。
5. **先测量再优化**：MT-1 的逐核/锁成本/原型数据直接否决了「全局总线锁」，并指出
   **睡眠核快进**才是最大单项（30.7 % 墙钟）——比盲目并行更有效。
6. **锁的形态决定成败**：2 线程全局互斥 8.97 ns/访问 vs 单线程 5.1 ns；10 bank 分片才可行；
   逐指令 Barrier 483 ns 完全不可用，批量窗口 64 步 ≈7.6 ns/步。

## 3. 测试与并发

7. **进程级全局状态必须隔离**：`flash::content_generation` 是全局原子，涉及
   `FlashRegion::new/write/erase` 的测试必须持 `flash_support::flash_generation_lock()`；
   否则并行 flake（本会话用确定性压力测试复现 8 万次 miss 才定位）。
8. **超时要区分「调度上限」与「卡死上限」**：插件 500 ms 超时在 16 线程负载下误杀健康
   worker；默认改为 5 s，卡死测试用按设备的短超时。
9. **并行测试要连跑 30 次**才算可信；单次绿可能是调度巧合。
10. **线程化语义要有可断言的等价物**：同步 vs 线程化逐 pin 一致、off vs on 计数器一致、
    `run_steps` vs 逐条 `step()` 一致；没有对照就没有确定性。

## 4. 工程操作

11. **长跑进程不要被验收命令误杀**：`Get-Process rp2350-cli | Stop-Process` 曾杀掉 soak；
    构建会锁 `target\release\*.exe`，soak 用复制出来的二进制。
12. **中文源文件不要用 PowerShell 整文件读写**（破坏 UTF-8）；用 `edit`/`write`，
    并检查 `U+FFFD` / BOM。
13. **`.gitignore` 的 `HANDOFF.md` 会（在 Windows 上）忽略 `doc/handoff.md`**；已改为
    `/HANDOFF.md` 只忽略根目录。
14. **发布卫生也是功能**：`LICENSE` 缺失、README 与实现相反、CHANGELOG 积压、版本号不动，
    都会让「已完成」的系统无法发布。

## 5. 子会话工作流

15. **一个任务 = 一个全新子会话**；禁止 follow-up 复用；返工也开新会话并附失败证据。
16. 主会话只做分析/拆分/派发/验收；功能代码交子会话；每波 ≤2 个 crate 不相交任务。
17. 子会话提示词必须自包含：目标、证据、白名单、验收命令、约束、报告模板；
    并明确「不得用放宽断言/忽略失败掩盖竞态」。
18. 验收必须**独立复跑**：子会话报告的数字只作参考；本会话多次发现子会话遗漏的 flake
    与口径错误，都是主会话复跑才暴露的。
